## Error Handling

Every error response (from `GlobalExceptionHandler`, a `@RestControllerAdvice`)
has this shape:

```json
{
  "status": 404,
  "message": "string",
  "fieldErrors": [ { "field": "string", "message": "string" } ] | null,
  "timestamp": "2026-07-30T12:00:00Z"
}
```

- `fieldErrors` is only populated for `400` bean-validation failures; `null` otherwise.
- `@JsonInclude(NON_NULL)` is set, so `fieldErrors` may be **omitted entirely**
  from the JSON when null, not just `null` — don't assume the key is always present.

### Exception → status mapping

| Status | Trigger | `message` content | `fieldErrors` |
|---|---|---|---|
| `400` | `MethodArgumentNotValidException` — any `@Valid` DTO fails bean validation | `"Validation failed"` (fixed string) | populated, one entry per failing field |
| `400` | `HttpMessageNotReadableException` — malformed/unparseable JSON body | `"Malformed request body"` (fixed string) | `null` |
| `401` | any subclass of abstract `UnauthorizedException` | **`"Unauthorized"` (fixed string — the exception's own message is discarded)** | `null` |
| `403` | any subclass of abstract `ForbiddenException` | the exception's own message | `null` |
| `404` | any subclass of abstract `NotFoundException` | the exception's own message | `null` |
| `409` | any subclass of abstract `ConflictException` | the exception's own message | `null` |
| `409` | `DataIntegrityViolationException` (DB constraint violation) | `"Data integrity violation"` (fixed string) | `null` |
| `422` | any subclass of abstract `UnprocessableEntityException` | the exception's own message | `null` |
| `500` | anything else (catch-all `Exception`) | `"Something went wrong"` (fixed string) | `null` |

**Important:** for `401`s specifically, the frontend cannot rely on the message
text to distinguish *why* auth failed (e.g. "invalid refresh token" vs "invalid
credentials") — the handler always returns the literal string `"Unauthorized"`.
Every other status category passes the real exception message through.

| Category | Class | Raised by (package) |

## Users / Auth

### `POST /api/v1/users/register`

**Auth:** public (in `SecurityPaths.PUBLIC_PATHS`).

Request (`RegisterRequest`):
```json
{
  "email": "string",         // @NotBlank, @Size(max=255), @Email
  "password": "string",      // @NotBlank, @Pattern: min 8 chars, upper+lower+digit+special (@$!%*?&)
  "firstName": "string",     // @NotBlank, @Size(max=50)
  "lastName": "string",      // @NotBlank, @Size(max=100)
  "mobileNumber": "string"   // no validation, optional
}
```
Password regex: `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]{8,}$`

Response `201` (`RegisterResponse`):
```json
{ "id": 0, "email": "", "firstName": "", "lastName": "", "mobileNumber": null,
  "role": "CUSTOMER" }   // Role enum: CUSTOMER | OWNER | STAFF | ADMIN
```
Errors: `400` (validation), `409` `DuplicateEmailException`.

### `POST /api/v1/users/login`

**Auth:** public (in `SecurityPaths.PUBLIC_PATHS`).

Request (`LoginRequest`): `{ "email": "string", "password": "string" }` (both `@NotBlank` only — no format/length checks on this endpoint).

Response `200` (`LoginResponse`): `{ "accessToken": "string", "refreshToken": "string" }`

Errors: `400` (validation — blank fields only), `401` `InvalidUserCredentialsException` → generic `"Unauthorized"` message.

### `POST /api/v1/users/refresh`

**Auth:** ⚠️ not in `SecurityPaths.PUBLIC_PATHS`, but see [Known gaps](#known-gaps--contradictions) — currently reachable without a token at the HTTP layer.

Request (`RefreshRequest`): `{ "refreshToken": "string" }` (`@NotBlank`)

Response `200`: `LoginResponse` (same shape as login — new access+refresh token pair).

Errors: `400` (validation), `401` `InvalidRefreshTokenException` → generic `"Unauthorized"` message.

### Not yet wired to a controller

- **Change password**: `ChangePasswordRequest` (`currentPassword` `@NotBlank`; `newPassword` `@NotBlank` + same password-strength `@Pattern` as register) exists and `UserService.changePassword(...)` exists, but **no `@RestController` endpoint calls it yet**. Don't build a "change password" form against a path yet — there isn't one.

## Admin

### `POST /api/v1/admin/owner`

**Auth:** requires `ROLE_ADMIN` — this is the **only** path with real enforcement in `SecurityConfig` (`requestMatchers("/api/v1/admin/**").hasRole("ADMIN")`).

Creates an owner user **and** their first theater in one call.

Request (`CreateOwnerRequest`):
```json
{
  "email": "string",        // @NotBlank, @Size(max=255), @Email
  "password": "string",     // @NotBlank, @Pattern: same strength rule as register
  "city": "string",         // @NotBlank, @Size(max=50)
  "theaterName": "string",  // @NotBlank, @Size(max=100)
  "address": "string"       // @Size(min=1, max=255) — NOT @NotBlank, so omitting entirely may pass; check empty-string handling
}
```

Response `201` (`CreateOwnerResponse`): `{ "ownerId": 0, "theaterId": 0 }`

Errors: `400` (validation), `409` (likely `DuplicateEmailException`, not confirmed from controller/exception alone — service-layer, out of scope).

## Movies

### `POST /api/v1/movies/batch`

**Auth:** open (`permitAll`).

Bulk-creates movies; partial success is possible (per-item, not all-or-nothing).

Request (`BulkCreateMovieRequest`): `{ "movies": [ CreateMovieRequest, ... ] }` (`@NotEmpty`, `@Valid` cascades to each item)

Each `CreateMovieRequest`:
```json
{
  "title": "string",                 // @NotBlank
  "duration": 0,                     // @NotNull (Integer, minutes)
  "releaseDate": "2026-01-01",       // @NotNull (LocalDate)
  "availableLanguages": ["string"],  // @NotEmpty
  "availableFormats": ["TWO_D"],     // @NotEmpty, MovieFormat: TWO_D | THREE_D
  "genre": ["string"],               // no validation, optional
  "cast": [ { "characterName": "", "actorName": "" } ]  // no validation, optional
}
```

Response `207 Multi-Status` (`MovieBatchResponse`): `{ "results": [ ... ] }` where each
item is **one of two shapes** (no discriminator field — distinguish by which keys are present):
```json
{ "index": 0, "movieId": "string", "title": "string" }      // success
{ "index": 0, "errorMessage": "string" }                    // failure
```

Errors: `400` if the *outer* request fails validation (e.g. empty `movies` array or a malformed item shape) — per-item business failures (e.g. duplicate movie) surface as `errorMessage` entries inside the `207`, not as a top-level error status.

> No `GET` endpoints exist for movies (no list, no get-by-id) — `movieId` and
> `movieTitle` only surface today embedded in `ShowResponse`.

## Known gaps / contradictions

Flagging these directly rather than silently picking an interpretation:

1. **`SecurityPaths.PUBLIC_PATHS` doesn't mean what you'd guess.** Your prompt
   said to use it to determine "requires authentication," but I read
   `SecurityConfig.java` too and the two don't agree:
   - `SecurityConfig`'s `authorizeHttpRequests` only requires a role for
     `/api/v1/admin/**` (`hasRole("ADMIN")`). **Every other path — including
     `/refresh`, theaters, movies, shows, screens, seats — is `.anyRequest().permitAll()`**
     at the Spring Security layer, regardless of whether it's in `PUBLIC_PATHS`.
   - `PUBLIC_PATHS` (register + login only) is consumed by `JwtAuthFilter`, not
     `SecurityConfig`. Its actual effect: for a `PUBLIC_PATHS` request, the JWT
     filter skips token parsing entirely. For any *other* path, the filter tries
     to parse a `Bearer` token **if one is present** (rejecting with `401` if it's
     invalid) but **does not require one** — no header at all just proceeds
     unauthenticated, and since almost everything is `permitAll`, the request
     still reaches the controller.
   - **Net effect right now:** only `POST /api/v1/admin/owner` is actually
     gated. Everything else (including show/screen/seat/theater creation) is
     callable with no token today. This is very likely a WIP state, not the
     intended long-term shape — worth confirming with yourself/the backend
     before building auth-gated UI around endpoints that aren't actually gated
     yet.

2. **Two DTOs exist with no controller wired to them yet:**
   - `CreateTheaterRequest` (`city`/`name`/`address`, no validation annotations
     applied despite the file importing `@NotBlank`/`@NotNull`/`@Size`) —
     `TheaterService.create(CreateTheaterRequest, User owner)` exists and has
     tests, but `TheaterController` has no `POST` mapping calling it. There is
     currently no way to create a standalone theater via the API — theaters
     are only created as a side effect of `POST /api/v1/admin/owner`.
   - `ChangePasswordRequest` — `UserService.changePassword(...)` exists but
     `UserController` has no endpoint for it.

   Don't build "create theater" or "change password" forms against guessed
   paths — they don't exist yet.

3. **Theater-staff feature has exceptions but no controller.** `DuplicateStaffException`,
   `UnauthorizedTheaterAccessException`, and `UserAlreadyHasRoleException` all
   exist under `theaterstaff/`, implying an add-staff-to-theater flow, but there's
   no `@RestController` for it anywhere in the codebase yet. Nothing to build
   against here yet.

4. Several `404` mappings in this doc (e.g. movie/screen-not-found on show/seat
   creation) are inferred from the exception classes existing, not confirmed
   from controller code — service-layer logic was intentionally out of scope
   for this read. Treat those as "likely" until confirmed by a real request.
